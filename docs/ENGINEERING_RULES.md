# Launchpad Engineering & Teaching Principles

## Core Pedagogical Directive

Every design decision, code implementation, test script, and refactoring step in this repository MUST be accompanied by an explicit, structured breakdown addressing four fundamental engineering dimensions:

---

### 1. WHAT We Are Doing
* Clear, concise definition of the immediate work item, artifact, or code modification.

### 2. HOW We Are Doing It
* Step-by-step technical execution details, architectural design patterns, SQL queries, and code structures.

### 3. WHY We Are Doing It
* The deep computer science, system design, or domain-driven design rationale behind the decision.

### 4. WHY It Is Necessary & Industry Best Practices
* **Production Reality**: What breaks in real-world high-traffic systems if this is omitted.
* **Industry Standards**: How senior backend engineers, staff architects, and distributed systems leads solve this problem at scale (e.g., Stripe, Ticketmaster, Netflix, AWS).
